Harbor System provides a comprehensive suite of security modules designed to protect your Discord server from a wide range of threats. Each module targets a specific attack vector and operates independently, so you can build a security configuration that matches your server's size, community type, and moderation capacity. Below is a full overview of every module currently available.

<AccordionGroup>
  <Accordion title="Anti-Raid Protection">
    Anti-Raid Protection monitors your server's join activity and detects coordinated raid attempts before they can disrupt your community. When a large number of accounts join within a short time window, Harbor System identifies it as a potential join flood and takes immediate action.

    **Threats addressed:**
    - Join floods from large groups of accounts arriving simultaneously
    - Mass-join events triggered by public raid calls
    - Coordinated raids using newly created or aged accounts

    **Key configuration options:**
    - Join threshold: set the number of joins within a time window (e.g., 10 joins per 30 seconds) that triggers a raid alert
    - Automated response action: choose between lockdown, kick, ban, or alert-only
    - Account age filter: automatically flag or reject accounts newer than 7 days old at join time
    - Raid lockdown mode: temporarily prevent all new joins until the threat is cleared
  </Accordion>

  <Accordion title="Anti-Nuke">
    Anti-Nuke protects your server's structure from destructive actions carried out by compromised administrator accounts or rogue moderators. It watches your audit log for mass deletion events and can freeze a user's permissions or ban them immediately when a nuke pattern is detected.

    **Threats addressed:**
    - Mass channel deletions by a single user in a short period
    - Mass role deletions that strip permissions from your entire member base
    - Bulk member bans or kicks executed maliciously

    **Key configuration options:**
    - Deletion threshold: the number of channels, roles, or members that can be deleted within 10 seconds before Anti-Nuke activates
    - Response action: strip permissions, ban the offending account, or both
    - Whitelist: exempt specific trusted administrator accounts from Anti-Nuke triggers
    - Notification target: designate a channel or role to be alerted when a nuke attempt is detected
  </Accordion>

  <Accordion title="Anti-Spam">
    Anti-Spam rate-limits message activity in your server to prevent channels from being flooded with repeated messages, excessive mentions, or emoji spam. It applies configurable cooldowns and takes automated action against members who exceed defined thresholds.

    **Threats addressed:**
    - Repeated identical or near-identical messages sent in rapid succession
    - Mention spam targeting large numbers of users or roles in a single message
    - Emoji floods that render channels unreadable
    - Rapid cross-channel message spreading

    **Key configuration options:**
    - Message rate limit: the number of messages allowed per user within 5 seconds before a warning or mute is applied
    - Mention limit: the maximum number of mentions permitted in a single message before action is taken
    - Emoji limit: the maximum number of emoji characters allowed per message
    - Escalation behavior: configure whether violations result in a warning, temporary mute, or kick based on repeat offense count
  </Accordion>

  <Accordion title="Anti-Bot">
    Anti-Bot identifies and blocks suspicious automated accounts from joining or participating in your server. It uses a combination of behavioral analysis and account characteristic checks to distinguish between legitimate users and bot accounts that have not been authorized.

    **Threats addressed:**
    - Unauthorized bot accounts joining to scrape member data or send spam
    - Automated accounts used in coordinated raids or manipulation campaigns
    - Self-bot activity that violates Discord's Terms of Service

    **Key configuration options:**
    - Account age minimum: automatically flag accounts newer than 7 days
    - Avatar check: flag accounts with no profile avatar as higher risk
    - Behavioral scoring: assign suspicion scores based on join timing, message patterns, and interaction behavior
    - Response action: choose to flag for review, kick, or ban detected bot accounts
  </Accordion>

  <Accordion title="Member Verification">
    Member Verification gates access to your server by requiring new members to complete a verification challenge before they can view or participate in channels. This filters out automated accounts and uninvited users at the point of entry.

    **Threats addressed:**
    - Bot accounts that join and immediately begin posting spam or scraping data
    - Raid accounts that rely on speed and volume to overwhelm moderation
    - Unverified or low-trust accounts accessing sensitive or public-facing channels

    **Key configuration options:**
    - Verification method: choose between CAPTCHA verification or reaction-based confirmation
    - Verification channel: designate the channel where new members complete the verification process
    - Verified role: specify the role granted to members who complete verification successfully
    - Timeout: set a time limit (e.g., 10 minutes) after which unverified members are kicked automatically
    - DM prompt: optionally send new members a direct message with verification instructions
  </Accordion>

  <Accordion title="Security Logs">
    Security Logs writes a timestamped record of every security event and bot action to a designated channel in your server. This gives your moderation team full visibility into what Harbor System is doing and why, and provides an audit trail for reviewing past incidents.

    **What is logged:**
    - All automated actions taken by Harbor System (warns, mutes, kicks, bans)
    - Triggered security module events with details on the offending account and rule matched
    - Configuration changes made via `/harbor config` commands
    - Anti-nuke and anti-raid activations with severity level

    **Key configuration options:**
    - Log channel: designate which channel receives security log output
    - Log verbosity: choose between concise summaries or detailed event entries
    - Module filter: enable or disable log output per individual security module
  </Accordion>

  <Accordion title="Threat Detection">
    Threat Detection provides real-time trust scoring for users in your server. Harbor System assigns each member a risk level based on behavioral signals, account characteristics, and activity patterns, and automatically flags or acts on accounts that cross a defined threshold.

    **Threats addressed:**
    - Sleeper accounts that join legitimately but exhibit malicious behavior over time
    - Low-trust accounts that match patterns associated with known bad actors
    - Users whose behavior changes suddenly, indicating a compromised or repurposed account

    **Key configuration options:**
    - Trust score threshold: set the score floor (e.g., 40 out of 100) below which an account is flagged
    - Scoring factors: configure which signals contribute to trust scoring (account age, join history, message behavior, etc.)
    - Response on flag: choose to notify moderators, apply a restricted role, or take automated action
    - Score review interval: set how frequently Harbor System re-evaluates active member scores
  </Accordion>

  <Accordion title="Whitelist System">
    The Whitelist System allows you to exempt specific users, roles, or bots from Harbor System's security rules. This ensures that trusted members, staff roles, and authorized bots are never incorrectly flagged or restricted by automated rules.

    **Use cases:**
    - Exempting moderator and administrator roles from anti-spam rate limits
    - Whitelisting authorized bots so Anti-Bot detection does not flag them
    - Protecting long-standing trusted members from new-account restrictions

    **Key configuration options:**
    - User whitelist: add individual user IDs to bypass all or specific security modules
    - Role whitelist: exempt all members with a given role from specified rules
    - Bot whitelist: authorize specific bot accounts to operate without restriction
    - Per-module exemptions: apply whitelist entries to specific modules rather than all rules globally
  </Accordion>

  <Accordion title="Slash Command Interface">
    Harbor System is fully controlled through Discord's native slash command interface using the `/harbor` command group. Every configuration option, security action, and status check is available directly in your server without any external tools or web portals.

    **What you can do:**
    - Run `/harbor setup` to initialize the bot and apply default settings
    - Use `/harbor config` subcommands to enable, disable, and tune each security module
    - Run `/harbor status` to review the current state of all active modules
    - Use `/harbor whitelist` to manage exemptions for users, roles, and bots
    - Run `/harbor logs` to pull a summary of recent security events

    **Key configuration options:**
    - Command access control: restrict `/harbor` commands to specific roles (e.g., your Moderator or Admin role)
    - Ephemeral responses: configure whether bot responses are visible only to the command user
    - Command channel restriction: limit which channels `/harbor` commands can be used in
  </Accordion>
</AccordionGroup>

<Tip>
  You can enable or disable any module independently without affecting other features.
</Tip>
