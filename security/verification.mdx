Verification is your server's first line of defense against bots, raiders, and low-effort throwaway accounts. When verification is enabled, every new member who joins is assigned an unverified role that blocks access to all server channels. Before they can interact with your community, they must complete a challenge in a dedicated verification channel. Once they pass, Harbor System assigns them the verified role and grants full access. This single gate eliminates a significant portion of automated threats before any other security module needs to act.

## Verification Modes

<Tabs>
  <Tab title="Reaction">
    In reaction mode, Harbor System posts a verification message in your verify channel. The new member must click a specific reaction on that message to confirm they are human and agree to your server rules.

    This mode is the lowest-friction option and works well for most community servers. It is effective against simple bots that do not interact with message reactions.
  </Tab>
  <Tab title="Button">
    In button mode, Harbor System posts an interactive message with a Discord button component. The new member clicks the button to complete verification.

    This mode uses modern Discord UI components and provides a cleaner user experience than reaction-based verification while offering comparable security.
  </Tab>
  <Tab title="CAPTCHA">
    In CAPTCHA mode, Harbor System presents the new member with a CAPTCHA challenge they must solve before gaining access. This mode offers the highest level of bot resistance and is recommended for servers that are frequent raid targets.

  </Tab>
</Tabs>

## How It Works

The verification flow follows these steps:

1. A new member joins the server.
2. Harbor System automatically assigns the **Unverified** role, which has no access to any server channels.
3. The member lands in the verification channel — the only channel they can see.
4. They complete the configured challenge (reaction, button, or CAPTCHA).
5. Harbor removes the **Unverified** role and assigns the **Verified** role.
6. The member now has full access to the server according to their role permissions.

## Setting Up Verification

Follow these steps to configure verification from scratch:

1. Create an **Unverified** role in your server settings with no channel view or send permissions — this role should be a complete access blocker.
2. Enable the verification module:
   ```bash
   /harbor verify enable
   ```
3. Set the channel where new members will complete verification:
   ```bash
   /harbor verify channel:#verify-here
   ```
4. Set the role Harbor assigns after a member successfully verifies:
   ```bash
   /harbor verify role:@Member
   ```
5. Set the role Harbor assigns to new members before they verify:
   ```bash
   /harbor verify unverified-role:@Unverified
   ```

Make sure your channel permissions are configured so that the **Unverified** role can only see the verification channel and nothing else.

## Configuration Options

| Option | Description | Default |
|---|---|---|
| `mode` | Verification challenge type (`reaction`, `button`, `captcha`) | `button` |
| `verify-channel` | Channel where the verification prompt is posted | none |
| `verified-role` | Role assigned after successful verification | none |
| `unverified-role` | Role assigned to new members before verification | none |
| `timeout` | Minutes before an unverified member is auto-kicked | none |

<Tip>
  Pair verification with anti-raid for maximum protection. Verification slows down raids significantly, buying time for Harbor's anti-raid module to trigger.
</Tip>
