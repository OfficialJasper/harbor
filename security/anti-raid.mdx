A Discord raid is a coordinated attack in which a large number of accounts join your server in a short period with the intent to spam channels, post harmful content, or disrupt your community. Harbor System's anti-raid module monitors your server's join rate in real time and automatically triggers a lockdown when suspicious join activity exceeds your configured threshold — stopping raids before they can cause damage.

## How Anti-Raid Works

Harbor System tracks every member join event and measures the rate of joins over a rolling time window. When the number of joins within that window exceeds your configured threshold, the module classifies the event as a raid and immediately activates lockdown mode. During lockdown, new joins are paused or gated behind a role restriction, and your moderation team is alerted. The detection algorithm is continuous — it does not require manual monitoring and resets automatically once join activity returns to normal levels.

## Enabling Anti-Raid

To enable anti-raid protection with default settings, run:

```bash
/harbor anti-raid enable
```

To customize the detection sensitivity at the same time, specify the `threshold` and `window` parameters:

```bash
/harbor anti-raid threshold:[NUMBER] window:[SECONDS]
```

- **threshold** — The maximum number of joins allowed within the time window before lockdown is triggered. For example, `threshold:5` means five joins in the window will activate the module.
- **window** — The length of the rolling time window in seconds. For example, `window:10` means Harbor evaluates joins over a 10-second period.

## Configuration Options

| Option | Description | Default | Example |
|---|---|---|---|
| `threshold` | Max joins in time window before lockdown | `[DEFAULT_THRESHOLD]` | `5` |
| `window` | Time window in seconds | `[DEFAULT_WINDOW]` | `10` |
| `action` | Action taken on detected raiders | `kick` | `ban` |
| `lockdown-mode` | How the server is locked during a raid | `role` | `channel` |
| `notify-role` | Role to ping when a raid is detected | none | `@Mods` |

## Lockdown Behavior

When anti-raid triggers a lockdown, Harbor System immediately restricts new member access according to your `lockdown-mode` setting. In `role` mode, incoming members are held at an unverified role that cannot see server channels. In `channel` mode, Harbor locks all public channels to prevent new interactions. Existing members are not affected and can continue using the server normally throughout the lockdown.

Your moderation team receives an alert in the configured log channel (and via a role ping if `notify-role` is set) detailing the number of joins that triggered the lockdown and the accounts involved.

To manually end a lockdown after reviewing the situation, run:

```bash
/harbor anti-raid unlock
```

This command lifts all lockdown restrictions and resumes normal join behavior.

## Whitelist

Certain bots or trusted accounts may join your server during legitimate events and should not be counted toward the raid threshold. Add them to Harbor's whitelist to exclude them from anti-raid detection:

```bash
/harbor whitelist add user:@BotName
```

For full details on managing the whitelist, see the [Whitelist](/reference/permissions) section.

<Warning>
  Setting the threshold too low (e.g., 2 joins in 10 seconds) may trigger false positives during legitimate server promotions or announcements.
</Warning>

<Tip>
  For large public servers, consider setting a higher threshold and pairing anti-raid with the verification module to pre-screen members.
</Tip>
