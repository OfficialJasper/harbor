This guide is for server owners who are setting up Harbor System from scratch on a new or recently created Discord server. Following this setup flow in order ensures every module is configured correctly before the next one is enabled, reducing the chance of gaps in your protection.

## Before You Begin

Make sure you have the following in place before running any commands:

- Harbor System added to your server (see [Installation](/getting-started/installation))
- A `#security-logs` channel created
- Roles created: **Admin**, **Moderator**, **Member**, **Unverified**
- Role hierarchy set correctly: Admin > Moderator > Harbor System Bot > Member > Unverified

<Steps>
  <Step title="Run the Setup Wizard">
    Run `/harbor setup` and follow all prompts. The wizard walks you through the foundational configuration and checks that Harbor has the permissions it needs to operate.
  </Step>
  <Step title="Set the Log Channel">
    Direct all security events to your dedicated log channel:

    ```
    /harbor logs channel:#security-logs
    ```
  </Step>
  <Step title="Assign Admin and Mod Roles">
    Tell Harbor which roles belong to your staff so it can respect your moderation hierarchy:

    ```
    /harbor config admin-role:@Admin
    /harbor config mod-role:@Moderator
    ```
  </Step>
  <Step title="Enable Verification">
    Configure the full verification flow so new members must complete a challenge before gaining access:

    ```
    /harbor verify enable
    /harbor verify channel:#verify-here
    /harbor verify role:@Member
    /harbor verify unverified-role:@Unverified
    ```
  </Step>
  <Step title="Configure Unverified Role Permissions">
    In Discord's server settings, review every channel and ensure the `@Unverified` role cannot read or send messages anywhere except `#verify-here`. This is a manual Discord-side step — Harbor enforces the verification flow, but Discord controls what unverified members can see.
  </Step>
  <Step title="Enable Anti-Raid">
    Turn on anti-raid detection to automatically respond to coordinated join surges:

    ```
    /harbor anti-raid enable
    ```
  </Step>
  <Step title="Enable Anti-Spam">
    Activate anti-spam to catch message flooding and repeated content from individual users:

    ```
    /harbor anti-spam enable
    ```
  </Step>
  <Step title="Enable Anti-Nuke">
    Turn on anti-nuke protection. This is especially important if your server has multiple admins, as it guards against compromised admin accounts being used to delete channels or mass-ban members:

    ```
    /harbor anti-nuke enable
    ```
  </Step>
  <Step title="Enable Threat Detection">
    Enable threat detection to continuously evaluate new members and flag accounts with suspicious indicators:

    ```
    /harbor threat-detection enable
    ```
  </Step>
  <Step title="Review Your Setup">
    Run a full health check to confirm all modules are active and Harbor has the permissions it needs:

    ```
    /harbor status
    ```

    Review each item in the output and resolve any warnings before opening your server to new members.
  </Step>
</Steps>

## Recommended Channel Structure

A well-organized channel structure reinforces Harbor System's protections at the Discord permission level.

- **Public channels** (e.g., `#general`, `#announcements`) should be locked to `@Member` only. Remove read access for `@everyone` and instead grant it explicitly to `@Member`. This ensures unverified users land in a restricted state automatically upon joining.
- **`#verify-here`** should be visible to `@everyone` (or specifically to `@Unverified`) so new members can see and complete the verification challenge. Keep this channel read-only for all other roles to prevent clutter.
- **`#security-logs`** should be restricted to `@Admin` and `@Moderator` only. Harbor posts sensitive event data there, and it should not be visible to general members.
- **Staff channels** should be locked to `@Moderator` and above, completely hidden from `@Member` and `@Unverified`.

<Tip>
  Take a screenshot of `/harbor status` after setup and keep it for reference. It gives you a quick overview to compare against if something changes later.
</Tip>
