Anti-raid configuration is not one-size-fits-all. A threshold that works perfectly for a 50-person community will trigger false positives on a 10,000-member server that regularly runs promotions. This guide helps you choose the right thresholds, lockdown mode, and response actions based on your server's size and activity patterns.

## Understanding Thresholds

Harbor's anti-raid detection is controlled by two settings: **threshold** and **window**.

- **Threshold** is the number of members that must join before Harbor considers it a raid.
- **Window** is the time period (in seconds) within which those joins must occur for the threshold to be reached.

If the number of joins within the window exceeds the threshold, Harbor treats it as a raid and executes your configured action.

Here are starting points based on server size:

| Server Size | Recommended Threshold | Recommended Window | Notes |
|---|---|---|---|
| Small (< 100 members) | 3 | 10s | More sensitive; low normal join rate |
| Medium (100–1,000 members) | 5 | 10s | Balanced for moderate organic growth |
| Large (1,000+ members) | 10–15 | 10s | Prevents false positives during promotions |

Adjust these values based on your server's observed join patterns. If you run regular events or promotions, temporarily raise your threshold beforehand, then lower it again after.

## Step-by-Step Configuration

<Steps>
  <Step title="Enable Anti-Raid">
    Turn on the anti-raid module:

    ```
    /harbor anti-raid enable
    ```
  </Step>
  <Step title="Set Threshold and Window">
    Configure the detection sensitivity. The example below uses settings appropriate for a medium-sized server:

    ```
    /harbor anti-raid threshold:5 window:10
    ```
  </Step>
  <Step title="Set the Response Action">
    Define what Harbor does to detected raiders. `kick` is a good starting point — it stops the raid without permanently banning accounts that may have been caught by mistake:

    ```
    /harbor anti-raid action:kick
    ```

    Accepted values: `kick`, `ban`, `mute`
  </Step>
  <Step title="Set the Notify Role">
    Configure a role to be pinged when a raid is detected, so your moderation team is alerted immediately:

    ```
    /harbor anti-raid notify-role:@Moderators
    ```
  </Step>
  <Step title="Pair with Verification (Optional)">
    Enabling verification alongside anti-raid creates a two-layer defense. Verification stops automated accounts before they gain access; anti-raid handles volume attacks that slip through:

    ```
    /harbor verify enable
    ```

    See [Setting Up Member Verification](/guides/setting-up-verification) for full configuration steps.
  </Step>
</Steps>

## Lockdown Modes

When a raid is detected, Harbor can lock down your server in one of two ways:

- **Role lockdown** — Harbor creates a temporary lock role and applies it to new members, preventing them from sending messages while the server is in lockdown. This is less disruptive and does not alter your existing channel permission structure.
- **Channel lockdown** — Harbor overrides channel permissions directly to deny messaging access for new members. This is more comprehensive but involves more permission changes to reverse.

Set your preferred lockdown mode with:

```
/harbor anti-raid lockdown-mode:role
```

Accepted values: `role`, `channel`

For most servers, `role` lockdown is the recommended starting point. Use `channel` lockdown if you need a stricter response or if your channel structure makes role-based lockdown less effective.

## Whitelist Important Bots

Bots that handle welcome messages, role assignments, or integrations may trigger anti-raid detection if they join your server during setup or testing — especially if multiple bots are added in quick succession. Add them to Harbor's whitelist to prevent false positives:

```
/harbor whitelist add bot:[BOT_ID]
```

Replace `[BOT_ID]` with the bot's Discord user ID. You can find this by enabling Developer Mode in Discord and right-clicking the bot's profile.

## Testing Anti-Raid

Before relying on anti-raid in a live environment, verify your configuration is correct:

- Run `/harbor anti-raid status` to review your current threshold, window, action, and lockdown mode without triggering a detection event.
- If you need to test with actual join activity, use a dedicated test server — not your production server.
- Harbor does not provide a simulated raid trigger command, so all live testing should be done in a controlled environment where false lockdowns have no impact.

<Warning>
  Do not set threshold to 1 — legitimate bulk joins from promotions will trigger false lockdowns. Always start with a value of at least 3.
</Warning>
